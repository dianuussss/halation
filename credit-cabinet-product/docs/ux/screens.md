# UX: экраны клиента и back-office (D7, часть 1)
Статус: готов · Версия: 1.0 · Обновлено: 2026-10-24
Связано с: R-03, R-06, R-21, R-23 · [04_user_stories](../product/04_user_stories.md) · [state_machine §2, §5](../process/state_machine.md) · [api_overview](../api/api_overview.md) · потоки [flows](flows.md)

## Решение в одном абзаце
11 клиентских и 5 банковских экранов. Каждый клиентский экран отвечает на три вопроса: **где я, что происходит, что делать дальше** (блок «Что дальше» обязателен). Статусы и тексты берутся только из state machine, числа — только из API (фронт ничего не считает, кроме отображения калькулятора из `/calculate`). Figma не обязательна: описания ниже + ASCII-вайрфреймы ключевых экранов достаточно для сборки. Для каждого экрана описаны состояния загрузки, ошибки и пустое.

## UX-принципы (PDF, с. 5, 9)
1. Пользователь без банковской экспертизы на каждом экране понимает, где он и что дальше.
2. Никакого внутреннего жаргона; термины — тултипом «?»: «Долговая нагрузка — доля выручки, которая уходит на платежи по кредитам», «ОКВЭД — код вида деятельности из реестра».
3. Загрузка, ошибка и пустое состояние описаны для каждого экрана.
4. Только веб (огр. 07), адаптив 360–1440 px, одна колонка < 768 px; доступность: контраст AA, фокус с клавиатуры, `label` у всех полей, ошибки связаны с полем (`aria-describedby`).
5. Все уведомления — внутри продукта (огр. 05).
6. Статус обновляется без перезагрузки (SSE, фолбэк polling 3 с).
7. Деньги: формат `3 000 000 ₽`, даты `07.11.2026`, время `14:32` (Europe/Moscow).
8. Демо-режим заметен, но не мешает: плашка «Демо-стенд, данные синтетические» в футере.

## Клиентские экраны

### S-01. Вход
Цель: войти под своей ролью за 1 действие (на демо — за 1 клик).
Вход: прямая ссылка, редирект при `401`.
Данные: `POST /auth/login`.
Блоки: логотип · форма (логин, пароль, «Войти») · блок «Тестовые учётки» (только `DEMO_MODE`): таблица логин / роль / для чего, кнопка «подставить».
Состояния: загрузка — кнопка со спиннером, поля заблокированы · ошибка — «Неверный логин или пароль» над формой · rate limit — «Слишком много попыток, попробуйте через минуту» · пустое — нет.
AC: US-C-01.

### S-02. Главная ЛК клиента
Цель: за 3 секунды понять, что с заявкой и что дальше; получить полезное по своей стадии (JTBD-3, R-07).
Вход: после входа; из логотипа в шапке.
Данные: `GET /me`, `GET /applications?active=true`, `GET /feed`, `GET /notifications?unread=true`, SSE активной заявки.
Блоки: шапка (компания ▾, колокольчик с счётчиком, профиль) · «Ваша заявка» (номер, продукт, сумма, мини-таймлайн, текущий шаг, «Что дальше», кнопка «Открыть») или CTA-баннер «Получить финансирование» при отсутствии активной заявки · лента (до 8 карточек: тип-метка, заголовок, текст, CTA, «Почему я это вижу?» → тултип с `reason`; ACTION закреплена сверху жёлтым) · завершённые заявки (свёрнуто).
Состояния: загрузка — скелетоны карточки и 3 карточек ленты · ошибка ленты — «Не удалось загрузить новости» + «Повторить», заявка при этом показывается · пустое — нет заявок: баннер «Получить финансирование» + онбординг-лента.

```
┌──────────────────────────────────────────────────────────┐
│ ◉ Кабинет  [Кофейня Зерно ▾]                  🔔2  Анна ▾ │
├──────────────────────────────────────────────────────────┤
│ Ваша заявка №1001 · Экспресс-оборотка · 4 000 000 ₽      │
│ ●──●──◐──○──○──○  Оценка                                 │
│ Что дальше: обычно до 4 часов. Сообщим здесь.  [Открыть] │
├──────────────────────────────────────────────────────────┤
│ 📌 ДЕЙСТВИЕ  Банку нужны уточнения по заявке №1001  [→]  │
│ СОВЕТ   Как банк оценивает долговую нагрузку   (?)почему │
│ ОТРАСЛЬ Общепит: что меняется в маркировке…    (?)почему │
└──────────────────────────────────────────────────────────┘
```
AC: US-C-02, US-C-15.

### S-03. Мастер потребности
Цель: от задачи к продукту без знания продуктовой линейки (JTBD-1, P-C1).
Вход: CTA «Получить финансирование» (S-02), OFFER-карточка ленты, «Подобрать другой вариант» (S-08).
Данные: `POST /products/recommend {purpose, amount, termMonths}`.
Блоки: вопрос 1 «На что нужны деньги?» — 4 крупные кнопки (Пополнить оборотные средства · Купить оборудование или транспорт · Закрыть кассовые разрывы / сезонные закупки · Другое) · вопрос 2 «Сколько и на какой срок?» — сумма, срок · результат: 1–3 карточки продуктов (первая помечена «Лучше всего подходит»), у каждой «Почему подходит» одной фразой, ставка «от …», платёж «от …», «Подробнее» → S-04 · (Should) «Сравнить» → таблица.
Состояния: загрузка — скелетоны карточек · ошибка — «Не удалось подобрать продукты» + «Повторить» · пустое — не бывает (для цели всегда есть продукт); сумма вне лимитов — подсказка у карточки «максимум 5 000 000 ₽».
AC: US-C-03, US-C-16.

### S-04. Карточка продукта и калькулятор
Цель: понять условия и посильность платежа до заявки (P-C1, P-C7).
Вход: S-03, OFFER-карточка.
Данные: `GET /products`, `POST /products/{code}/calculate` (debounce 300 мс).
Блоки: название и описание · условия (сумма, срок, ставка «от», залог) · калькулятор: слайдер + поле суммы, слайдер + поле срока → «Платёж от … ₽/мес», «Переплата от … ₽», мелко «Точные условия — после оценки заявки» · «Что понадобится» — чек-лист документов · (Should) «Ваши шансы» · кнопка «Оформить заявку» → T0 → S-05.
Состояния: загрузка расчёта — значение платежа с шиммером · ошибка — «Не удалось рассчитать, попробуйте ещё раз» · вне лимитов — ошибка у поля, «Оформить» неактивна.
AC: US-C-05, US-C-17.

### S-05. Анкета (многошаговая)
Цель: собрать заявку с минимумом ручного ввода (JTBD-2, P-C3, P-C6).
Вход: «Оформить заявку» (S-04), ACTION «Заявка не отправлена».
Данные: `POST /applications` (T0), `PATCH /applications/{id}` (автосохранение), `GET /companies/lookup`, `POST /applications/{id}/documents`, `POST /applications/{id}/submit` (T1).
Блоки: прогресс-бар 5 шагов с возможностью вернуться · «Сохранено в 14:32» · «Вернуться позже».
1. **Компания:** ИНН → автозаполнение (метка «из реестра» / «изменено вами»), блок ликвидированной компании, ручной ввод при `404`.
2. **Финансы:** выручка за последний год, за предыдущий, расходы в месяц, платежи по текущим кредитам в месяц — у каждого поля тултип «зачем банку».
3. **Параметры кредита:** продукт (из S-04, можно сменить), цель, сумма, срок; платёж пересчитывается.
4. **Документы:** чек-лист продукта, загрузка drag&drop/кнопкой, статус каждого; предупреждение при пропуске обязательного.
5. **Согласия и проверка:** сводка всех шагов с «Изменить»; чекбоксы «Согласие на обработку данных», «Согласие на запрос в бюро кредитных историй» (с текстом-заглушкой); «Отправить заявку».
Состояния: загрузка lookup — спиннер в поле ИНН (≤ 2 с) · ошибка автосохранения — баннер с автоповтором · ошибка отправки `409 DUPLICATE` — модалка со ссылкой на активную заявку · пустое — новый черновик с предзаполнением из прошлой заявки компании, если она есть.
AC: US-C-04, US-C-06, US-C-07, US-C-08.

### S-06. Карточка заявки / статус
Цель: клиент понимает, где заявка и что дальше (JTBD-3, P-C2).
Вход: S-02 (карточка заявки), уведомление, STATUS-карточка ленты.
Данные: `GET /applications/{id}`, `GET /applications/{id}/events`, SSE `GET /applications/{id}/stream`.
Блоки: шапка (номер, продукт, сумма, срок, дата подачи) · вертикальный таймлайн 6 шагов: пройденные — ✓ и время, текущий — заголовок и пояснение из state_machine §2, будущие — серые · «Что дальше» (текст статуса + SLA) · плашка действия по статусу (NEEDS_INFO — жёлтая «Ответить на запрос» → S-07; решение — «Посмотреть решение» → S-08; SIGNING → S-09) · история событий (клиентские заголовки) · «Отозвать заявку» (только DRAFT, NEEDS_INFO, MANUAL_REVIEW, с подтверждением).
Состояния: загрузка — скелетон · ошибка сети/обрыв SSE — баннер «Нет соединения, обновляем…», переход на polling · NEEDS_INFO — жёлтая плашка · терминальный — итоговая плашка (зелёная DISBURSED / серая CANCELLED, EXPIRED / нейтральная REJECTED).

```
┌ Заявка №1001 · Экспресс-оборотка · 4 000 000 ₽ · 12 мес ┐
│ ✓ Заявка            24.10 12:00                           │
│ ✓ Проверка данных   24.10 12:01                           │
│ ◐ Оценка — Оцениваем заявку                               │
│   Оцениваем финансовое положение бизнеса                  │
│ ○ Решение   ○ Подписание   ○ Выдача                       │
├───────────────────────────────────────────────────────────┤
│ Что дальше: обычно до 4 часов. Сообщим здесь, в кабинете. │
│ История ▸                               [Отозвать заявку]  │
└───────────────────────────────────────────────────────────┘
```
AC: US-C-08, US-C-18.

### S-07. Запрос информации (NEEDS_INFO)
Цель: ответить на запрос, не начиная заново (JTBD-4, P-C5).
Вход: S-06, ACTION-карточка ленты, уведомление.
Данные: `GET /applications/{id}/info-request`, `POST /applications/{id}/documents`, `POST /applications/{id}/info-response` (T6).
Блоки: плашка «Банку нужны уточнения» + срок ответа · комментарий (от системы: «Не хватает документов из чек-листа»; от эксперта — его текст) · список пунктов: FILE — загрузка; FIELD — поле с текущим значением и вариантами («Адрес из реестра верный» / «Указать другой адрес» + документ) · счётчик «Осталось: N» · «Отправить ответ» (активна, когда N = 0).
Состояния: загрузка — скелетон · ошибка загрузки файла — у пункта · пустое — запроса нет (переход по старой ссылке) → «Запрос уже закрыт» + ссылка на заявку · EXPIRED — «Срок ответа истёк».
AC: US-C-09.

### S-08. Результат решения
Цель: понять решение, причины и варианты (JTBD-5, P-C4, P-C7).
Вход: S-06, STATUS-карточка, уведомление.
Данные: `GET /applications/{id}/offer`, `GET /applications/{id}` (для отказа), `POST …/offer/accept` (T18), `POST …/offer/decline` (T19).

| Исход | Заголовок | Содержание | CTA |
| --- | --- | --- | --- |
| APPROVED | «Заявка одобрена» | Сумма, срок, ставка, платёж, переплата, «действует до» | «Принять и подписать» · «Отказаться» |
| APPROVED_WITH_CHANGES (сумма/срок) | «Можем предложить другие условия» | Таблица «Вы просили / Мы предлагаем» с подсветкой изменений; фраза «почему»; топ-3 фактора | «Принять» · «Отказаться» |
| APPROVED_WITH_CHANGES (другой продукт) | «Вам больше подойдёт кредитная линия» | Карточка альтернативного продукта, чем отличается, платёж/проценты | «Принять» · «Отказаться» |
| REJECTED | «Сейчас не можем одобрить» | Топ-3 причины простыми словами, «Что можно сделать», «Подать снова можно через 3 месяца»; тон без обвинений | «Подобрать другой вариант» (кроме класса D) · «На главную» |
| NEEDS_INFO | → S-07 | — | — |
| MANUAL_REVIEW | «Заявку изучает специалист» | Ожидаемое время, что происходит | «К заявке» |

```
┌ Можем предложить другие условия ─────────────────────────┐
│               Вы просили        Мы предлагаем            │
│ Сумма         4 000 000 ₽   →   3 000 000 ₽   ▲изменено   │
│ Срок          12 мес            12 мес                   │
│ Ставка        от 22%        →   24%                       │
│ Платёж        от 374 378 ₽  →   283 679 ₽                 │
│ Почему: по результатам оценки мы можем сразу одобрить     │
│ до 3 000 000 ₽.                                           │
│ Что повлияло: − заметная долговая нагрузка                │
│  + вы давно обслуживаетесь в банке  + хорошая история     │
│ Предложение действует до 03.11.2026                       │
│                 [Отказаться]   [Принять и подписать]      │
└───────────────────────────────────────────────────────────┘
```
Состояния: загрузка — скелетон · ошибка — «Не удалось загрузить решение» + «Повторить» · оффер истёк — заголовок «Срок предложения истёк», кнопки скрыты.
AC: US-C-10, US-C-11.

### S-09. Подписание (имитация)
Цель: завершить сделку внутри продукта без SMS (огр. 05, 06).
Вход: «Принять» на S-08, STATUS «Осталось подписать договор».
Данные: `GET /applications/{id}/signing`, `POST /applications/{id}/sign` (T21), `POST …/offer/decline` (T24).
Блоки: пометка «Демо-режим: подпись юридической силы не имеет» · договор-заглушка (скролл, параметры оффера, график-выдержка) · (Should) «Скачать PDF» · чекбокс «Ознакомлен с условиями договора» · блок «Ваш код подтверждения: 482 913» и поле для ввода · «Подписать» · «Отказаться от кредита».
Состояния: загрузка — скелетон договора · неверный код — ошибка у поля и счётчик попыток · 3 ошибки — «Мы сгенерировали новый код» · истёк — «Срок предложения истёк».
AC: US-C-12.

### S-10. Кредит выдан
Цель: подтвердить результат и дать план платежей.
Вход: после T21; STATUS «Кредит выдан».
Данные: `GET /applications/{id}/loan`.
Блоки: заголовок «Кредит выдан» и короткая анимация (без излишеств) · «3 000 000 ₽ зачислены на расчётный счёт (демо)» · ближайший платёж: дата, сумма · график (таблица: дата, платёж, основной долг, проценты, остаток; на мобильном — карточками) · «На главную».
Состояния: загрузка — скелетон · ошибка — «Не удалось загрузить график» + «Повторить» · пустое — не бывает.
AC: US-C-13.

### S-11. Уведомления
Цель: история событий без email/SMS.
Вход: колокольчик.
Данные: `GET /notifications`, `POST /notifications/{id}/read`.
Блоки: список (иконка типа, текст, время, ссылка «К заявке»), непрочитанные жирным, «Отметить все прочитанными».
Состояния: загрузка — скелетон · ошибка — «Повторить» · пустое — «Здесь появятся события по вашим заявкам».
AC: US-C-14.

## Back-office

### B-01. Очередь заявок
Цель: начать с самых срочных и сложных заявок (JTBD-6, P-B6).
Вход: после входа эксперта.
Данные: `GET /backoffice/applications?status=MANUAL_REVIEW&sort=sla`, обновление каждые 5 с.
Блоки: счётчики по статусам (кликабельные фильтры) · фильтры: статус, продукт, класс риска, причина маршрута · поиск по ИНН / номеру · таблица: №, компания, ИНН, продукт, сумма, статус, класс, причина (`Залог`, `Серая зона`, `Неполные данные`), время в статусе, SLA-индикатор · строка → B-02.
Состояния: загрузка — скелетон строк · ошибка — баннер + «Повторить» · пустое — «Нет заявок, требующих решения 🎉» и ссылка «Показать все».
AC: US-B-01.

### B-02. Карточка эксперта
Цель: решение без переключения систем (P-B4).
Вход: B-01.
Данные: `GET /backoffice/applications/{id}`, `GET /backoffice/documents/{docId}`.
Блоки: шапка (№, компания, ИНН, продукт, сумма/срок, статус, класс, «Подал: ФИО, роль») · баннер флагов (неполные данные, расхождения) · вкладки:
- **Анкета** — данные клиента, метки источника полей.
- **Реестры `[MOCK]`** — ЕГРЮЛ/ЕГРИП и «Прозрачный бизнес»; расхождения подсвечены, оба значения рядом.
- **Кредитная история `[MOCK]`** — история, худшая просрочка, запросы, активные кредиты.
- **Скоринг** — баллы и класс, таблица факторов (значение, баллы, пояснение), версия правил, история скорингов «465 → 490» с diff факторов, нагрузка.
- **Документы** — список, просмотр/скачивание, статус.
- **История** — все события с переходами и авторами.
Справа — панель решения (B-03).
Состояния: загрузка — скелетон вкладок · ошибка — «Повторить» · неполные данные — баннер «Кредитная история не получена после 3 попыток», вкладка «Скоринг не рассчитан».

### B-03. Панель решения
Цель: зафиксировать решение с обоснованием (JTBD-7).
Данные: `POST /backoffice/applications/{id}/decision` (T16), `POST …/info-request` (T17).
Блоки: 4 действия-переключателя:
- **Одобрить** — поля предзаполнены рекомендованным оффером, read-only.
- **Одобрить с изменениями** — сумма, срок, ставка, (Should) продукт; комментарий обязателен; превью платежа.
- **Запросить информацию** — чек-лист (документы из справочника + поля анкеты: адрес, выручка, ОКВЭД), комментарий клиенту обязателен.
- **Отказать** — причина из справочника + внутренний комментарий; превью текста, который увидит клиент.
Подтверждение «Вы уверены? Решение увидит клиент» → отправка.
Состояния: отправка — кнопка со спиннером · `409` — «Заявка изменилась, обновите карточку» · `422` — ошибки у полей.
AC: US-B-03, US-B-04, US-B-05, US-B-06.

### B-04. Дашборд конвейера (Should)
Блоки: период · воронка по шагам · доля авто-решений · среднее время по статусам · заявки с нарушением SLA (ссылки). Пустое — «Нет заявок за период».
AC: US-B-07.

### B-05. Журнал аудита + сброс демо
Цель: проверяемость процесса и детерминированное демо.
Данные: `GET /backoffice/audit`, `POST /admin/demo/reset`.
Блоки: фильтры (номер заявки, тип инициатора, период) · таблица: время, заявка, переход (T-код), из → в, инициатор, причина · кнопка «Сбросить демо» (только `DEMO_MODE`, с подтверждением) · (Should) ссылка «Лента глазами клиента».
Состояния: загрузка — скелетон · ошибка — «Повторить» · пустое — «Событий пока нет».
AC: US-B-08, US-B-09.
