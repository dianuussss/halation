# Правила персональной новостной ленты (D8)
Статус: готов · Версия: 1.0 · Обновлено: 2026-10-24
Связано с: R-07, R-21 · P-C1, P-C2, P-C4, P-C5 · US-C-15, US-B-10 · конфиг [`config/feed_rules.yaml`](../../config/feed_rules.yaml) · проверка [`tools/reference/feed_demo.py`](../../tools/reference/feed_demo.py)

## Решение в одном абзаце
Лента — **навигатор по кредитному пути, а не рекламный баннер**: верх ленты всегда отвечает на вопрос «что сейчас с моей заявкой и что мне сделать», ниже — подсказки к текущей стадии, затем отраслевые новости. Персонализация — на объяснимых правилах (без ML): у каждой карточки есть условия аудитории и поле `reason`, которое клиент видит по клику «Почему я это вижу?». Лента меняется от **клиента** (отрасль, роль, размер, форма бизнеса) и от **стадии заявки** — это и есть отдельный пункт демо (PDF, с. 7). В seed 39 карточек; порядок для демо проверен эталонным ранжированием.

## 1. Типы карточек

| Тип | Пример | Назначение | Когда |
| --- | --- | --- | --- |
| ACTION | «Банку нужны уточнения по заявке №1001» | Не потерять заявку (P-C5) | Только когда процесс ждёт клиента: NEEDS_INFO, незавершённый DRAFT. Закрепляется сверху |
| STATUS | «Заявка №1001 на оценке. Обычно это занимает до 4 часов» | Прозрачность статуса (P-C2) | Текущий статус активной заявки; тексты = state machine |
| TIP | «Как банк оценивает долговую нагрузку» | Снижение страха и неопределённости (P-C4) | Привязка к стадии, продукту, роли, размеру бизнеса |
| OFFER | «Для сезонных закупок подойдёт кредитная линия» | Подбор продукта (P-C1) | Нет заявок / после выдачи / после отказа не по классу D. **Классу D не показывается** |
| INDUSTRY | «Общепит: что меняется в маркировке продукции с 1 ноября (демо)» | Ценность вне кредита, удержание | По ОКВЭД |
| PROGRAM `[ДОПУЩЕНИЕ]` | «Поручительство фонда поддержки МСП (демо)» | Альтернативный путь к финансированию | После отказа, по отрасли |
| SYSTEM | «Демо-стенд: все данные синтетические» | Сервисное | Всегда, внизу |

**Почему предложение оффера — STATUS с кнопкой, а не ACTION:** ACTION зарезервирован за блокирующими запросами банка; принять или отклонить оффер — выбор клиента, а не обязанность.

Все тексты — синтетические, помечены «(демо)», не содержат утверждений о реальных условиях банка или господдержки; это указано в README и THIRD_PARTY_NOTICES.

## 2. Сигналы персонализации

| Сигнал | Откуда | Поле `audience` | Пример влияния |
| --- | --- | --- | --- |
| Стадия активной заявки | Application.status | `application_status` | NEEDS_INFO → ACTION закреплена первой |
| Нет заявок | Application | `no_application` | Онбординг «Как выбрать кредит», OFFER по отрасли |
| Продукт заявки | Application.productCode | `product`, `exclude_product` | INVEST → TIP про залог; LINE → «как работает линия» |
| Отрасль | Company.okved `[MOCK ЕГРЮЛ]` | `okved_prefix` | 56.\* → новости общепита; 49.\* → логистики |
| Размер и форма бизнеса | Анкета, Company.legalForm | `revenue_lt`, `legal_form` | ИП < 10 млн ₽ → «Как подготовить отчётность ИП» |
| Роль пользователя в компании | Membership.companyRole | `role` | Бухгалтер → «Чек-лист документов для бухгалтера» |
| Класс риска | ScoringResult (сервер, клиенту не показывается) | `exclude_risk_class` | Класс D → OFFER скрыты |
| Новое событие | ApplicationEvent | (триггер пересчёта) | STATUS-карточка обновляется ≤ 5 с |

## 3. Алгоритм ранжирования (объяснимый)
1. **Отбор:** карточка попадает в кандидаты, если **все** условия `audience` совпадают с профилем.
2. **Балл** = приоритет типа (ACTION 100, STATUS 80, OFFER 50, TIP 40, PROGRAM 30, INDUSTRY 20, SYSTEM 10) + `priority_boost` карточки + 30 за привязку к стадии + 20 за привязку к отрасли − 1 за день возраста − 15, если уже показана.
3. ACTION закреплена сверху до выполнения действия.
4. Не более 2 карточек одного типа подряд; всего до 8 на главной.
5. Каждая карточка в `GET /feed` содержит `reason`; плейсхолдеры (`{number}`, `{sla}`, `{offer_expires}`, `{items}`, `{next_payment}`) подставляет сервер.
6. Пересчёт — при каждом `GET /feed` (дёшево: < 50 правил); кэш не нужен.

Пример правила:
```yaml
- id: tip_debt_load
  type: TIP
  title: "Как банк оценивает долговую нагрузку"
  body: "Долговая нагрузка — доля выручки, которая уходит на платежи по кредитам. Комфортно — до 30%."
  audience:
    application_status: [SCORING, DECISION_PENDING, MANUAL_REVIEW]
  priority_boost: 30
  reason: "Ваша заявка сейчас на этапе оценки"
```
