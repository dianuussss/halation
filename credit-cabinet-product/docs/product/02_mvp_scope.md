# Границы MVP (D2)
Статус: готов · Версия: 1.0 · Обновлено: 2026-10-24
Связано с: R-02, R-16, R-18…R-23 · P-C1…P-C8, P-B1…P-B7 · [01_research](01_research.md) → [03_story_map](03_story_map.md), [state_machine](../process/state_machine.md)

## Решение в одном абзаце
MVP — **один сквозной кредитный путь** «потребность → заявка → проверка → оценка → решение → подписание → выдача» для трёх продуктов, двух банковских ролей и одной автоматической системы, с честно смоделированными внешними интеграциями. Три продукта выбраны так, чтобы одна и та же оценка риска давала разные исходы (PDF, с. 14) и чтобы в демо были все пять исходов решения (PDF, с. 15). Всё, что не нужно для этого пути, — вне MVP или за флагом (ИИ, OCR). Критерий отсечения: «без этого жюри не пройдёт E2E-01…E2E-05» → Must; иначе — Should/Could.

## 1. Границы процесса
- **Начало:** у предпринимателя возникла потребность — он входит в кабинет и выбирает цель финансирования (PDF, с. 13).
- **Конец:** статус `DISBURSED` (имитация выдачи, сформирован график) **или** терминальный `REJECTED` / `CANCELLED` / `EXPIRED`.
- **Вне процесса:** обслуживание выданного кредита (платежи, реструктуризация), повторные кредиты в рамках лимита — только карточка кредита и график.

## 2. Кредитные продукты (3)

| Продукт | Цель | Сумма | Срок | Базовая ставка | Залог | Модель платежа | Документы | Зачем в MVP |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| «Экспресс-оборотка» `EXPRESS` | Оборотные средства, кассовый разрыв | 0,3–5 млн ₽ | 3–24 мес. | 22% | Нет | Аннуитет | Налоговая декларация | Быстрый путь, авто-решение, контроффер по сумме |

## 3. Роли

| Роль | Приоритет | Что делает в MVP |
| --- | --- | --- |
| Клиент (представитель МСП: собственник, гендиректор, бухгалтер, уполномоченный) | Must | Подбор продукта, заявка, документы, статус, ответ на запрос, принятие/отказ от оффера, подписание (имитация), просмотр кредита, лента |
| Кредитный эксперт | Must | Очередь, карточка заявки, решение по MANUAL_REVIEW: одобрить / с изменениями / отказать / запросить информацию |
| Администратор | Must (минимум) + Should | **Must:** журнал аудита (read-only), сброс демо-данных. **Should:** дашборд конвейера, лента «глазами клиента» |
| Система | Must | Валидация, обогащение `[MOCK]`, скоринг, авто-решение, таймеры, события ленты |

> Решение по открытому вопросу ТЗ «админ в Must или Should»: в Must только журнал аудита и сброс демо — оба нужны для E2E-01 (шаг 10) и детерминированного демо, стоят ~0,5 чел.-дня. Подробнее: [05_decisions](05_decisions.md#d-06).

## 4. In scope / Out of scope

| Блок | Входит в MVP | Не входит | Почему |
| --- | --- | --- | --- |
| Вход | Логин/пароль по тестовым учёткам, JWT, роли RBAC | Госуслуги, вход по ЭЦП, 2FA по SMS | Огр. 05 (без SMS), огр. 04 (автономность) |
| Компания | Профиль компании, роль пользователя в компании, несколько компаний у пользователя (sidorov) | Приглашение сотрудников, управление доверенностями | P-C8 закрыт ролью; приглашения — после MVP |
| Подбор продукта | Мастер по цели + рекомендации с «почему» + калькулятор | Маркетплейс продуктов, индивидуальные ставки до заявки | 3 продуктов достаточно, чтобы показать логику (P-C1) |
| Данные компании | Автозаполнение по ИНН `[MOCK ЕГРЮЛ/ЕГРИП]`, метка «из реестра» | Реальные запросы в ФНС | Огр. 04; смысл интеграции сохранён в моке |
| Анкета | 5 шагов, автосохранение, валидация ИНН/лимитов | Импорт банковской выписки, интеграция с 1С | P-C3, P-C6; импорт — Could |
| Документы | Загрузка PDF/JPG/PNG ≤ 10 МБ по чек-листу, статус проверки | Проверка подлинности; OCR — Could | Основной сценарий важнее (рек. 05) |
| Кредитная история | `[MOCK БКИ]` — детерминированный ответ по ИНН, режим сбоя (таймаут) | Реальные БКИ | Огр. 02, 04 |
| Проверка руководителей | `[MOCK «Прозрачный бизнес»]` — стоп-фактор SF-04 | Реальный сервис ФНС | Огр. 04 |
| Скоринг | Стоп-факторы + балльная карта + классы A–D, версия правил, факторы с вкладом | ML-модель | Нет данных для обучения и валидации; объяснимость важнее (PDF, с. 14) |
| Решение | 5 исходов: одобрено, одобрено с изменениями (сумма/срок), другой продукт, запрос информации, отказ | Кредитный комитет, многоуровневое согласование | Небинарность (PDF, с. 15) без лишней иерархии |
| Ручное рассмотрение | 1 эксперт, общая очередь, карточка, панель решения | Распределение по лимитам полномочий, «четыре глаза» | Сложность > ценность для демо; описано в roadmap |
| Подписание | Договор-заглушка + чекбокс + код подтверждения **на экране** | Реальная ЭЦП/КЭП, SMS-код | Огр. 05, 06 |
| Выдача | Имитация зачисления, кредит и график платежей | Движение средств, АБС | Огр. 06 |
| Уведомления | In-app: колокольчик, лента, таймлайн | Email, SMS, push, мессенджеры | Огр. 05 |
| Новостная лента | Персонализация по правилам + `reason` «Почему я это вижу» | Рекомендательная ML-система | Правила объяснимы и демонстрируемы (PDF, с. 7) |
| Back-office | Очередь, карточка, решение, журнал аудита, сброс демо | Дашборд (Should), управление правилами в UI (Could) | Must = то, что нужно для E2E |
| ИИ | **Could:** объяснение решения и сводка для эксперта на open-weights LLM за флагом `LLM_ENABLED`, шаблонный фолбэк | Обязательная зависимость от LLM; ИИ не принимает решений | Огр. 08, рек. 05 |
| Сопровождение кредита | Карточка выданного кредита и график | Платежи, досрочное погашение, реструктуризация | Вне границ «заявка → результат» |
| Интерфейс | Адаптивный веб 360–1440 px | Мобильное приложение | Огр. 07 |

## 5. Что имитировано и как сохранён смысл

| Имитация | Что запрашиваем | Что получаем | Как используем |
| --- | --- | --- | --- |
| `[MOCK ЕГРЮЛ/ЕГРИП]` | ИНН | Наименование, ОГРН, статус, дата регистрации, адрес, ОКВЭД, руководитель | Автозаполнение, стоп-факторы SF-01/SF-03, фактор «срок деятельности», сверка расхождений |
| `[MOCK «Прозрачный бизнес»]` | ИНН | Руководители/учредители, признак дисквалификации | Стоп-фактор SF-04 |
| `[MOCK БКИ]` | ИНН + согласие клиента | Наличие истории, худшая просрочка за 12 мес., текущая просрочка, запросы за 30 дней | Факторы скоринга, стоп-фактор SF-02 |
| `[MOCK внутренние данные банка]` | ИНН | Срок обслуживания р/с | Фактор «клиент банка» |
| Подписание | — | Код подтверждения на экране | Переход SIGNING → DISBURSED |
| Выдача | — | Кредит + график аннуитетных платежей | Экран «Кредит выдан», лента |

Моки — отдельный сервис (контейнер), отвечают по ИНН из seed, на неизвестный ИНН — `404`, у компании C6 — `504` (сценарий отказоустойчивости).

## 6. Блок для README (копируется как есть)

> **Границы MVP.** Прототип покрывает путь от выбора цели финансирования до выдачи кредита (имитация) для трёх продуктов: «Экспресс-оборотка», «Инвест-кредит», «Кредитная линия». Роли: клиент, кредитный эксперт, администратор (журнал аудита, сброс демо), автоматическая система.
> **Вошло:** мастер подбора, калькулятор, анкета с автозаполнением по ИНН и черновиком, документы по чек-листу, живой таймлайн статусов, запрос и дозагрузка информации, скоринг на правилах с объяснением, 5 исходов решения, ручное рассмотрение, подписание кодом на экране, график платежей, персональная новостная лента, журнал аудита.
> **Имитировано:** ЕГРЮЛ/ЕГРИП, «Прозрачный бизнес», БКИ, внутренние данные банка, подписание, выдача — локальный сервис моков с детерминированными ответами.
> **Не вошло:** реальные интеграции и ЭЦП, ML-скоринг, кредитный комитет, email/SMS/мессенджеры, мобильное приложение, обслуживание кредита.
> **ИИ:** опционально (`LLM_ENABLED`, только open-weights), объясняет решение простыми словами; при выключении работает шаблон, сценарий не меняется.
